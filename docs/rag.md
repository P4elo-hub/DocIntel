# RAG на LlamaIndex (Б5.3)

Минимальный RAG поверх дипломного сервиса: корпус из 10 документов индексируется
в Qdrant через LlamaIndex, ответ строится строго по найденному контексту с
цитатами на источники. Параллельно тот же запрос реализован «руками» (без
фреймворка) — для сравнения.

## Зависимости

Ставится метапакет-бандл плюс две интеграции, которых в бандле нет:

```bash
pip install llama-index                       # ядро + OpenAI LLM и эмбеддинги
pip install llama-index-vector-stores-qdrant  # интеграция с Qdrant
pip install llama-index-readers-file          # парсеры PDF / DOCX / HTML для SimpleDirectoryReader
```

Зафиксированные версии (проверены на живом Qdrant + OpenAI):

| Пакет | Версия |
|-------|--------|
| `llama-index` (бандл) | 0.14.22 |
| `llama-index-core` | 0.14.22 |
| `llama-index-embeddings-openai` | 0.6.0 |
| `llama-index-llms-openai` | 0.7.8 |
| `llama-index-vector-stores-qdrant` | 0.8.8 |
| `llama-index-readers-file` | 0.6.0 |
| `qdrant-client` | 1.15.1 |
| `openai` | 2.37.0 |

Модели: эмбеддинги `text-embedding-3-small` (dim 1536), LLM `gpt-5.4-mini`,
`temperature=0`. Всё настраивается в `app/core/config.py` / `.env`, не хардкодом.

> Метапакет `llama-index` 0.14 включает только `core`, `embeddings-openai`,
> `llms-openai` и `nltk`. Ридеры файлов (`readers-file`) и интеграция с Qdrant в
> бандл **не входят** — ставятся отдельно.

## Решение по коллекции

Коллекция из Б5.2 (`documents`) **не переиспользуется**. Причины:

1. Это другой корпус (120 чанков FAQ против 10 документов этого блока) —
   сравнивать ответы на разных данных нельзя.
2. Она наполнялась напрямую через `qdrant-client` с плоским payload
   `{text, source, category, created_at}`. LlamaIndex хранит ноды в своём
   формате (`_node_content` с метаданными и связями), поэтому при подключении к
   «чужой» коллекции через `from_vector_store` метаданные и цитаты `source_nodes`
   будут неполными.

Заведены две отдельные коллекции на одном корпусе и одной embed-модели:

| Коллекция | Кто пишет | payload | Зачем |
|-----------|-----------|---------|-------|
| `rag_block_03` | LlamaIndex (`from_documents`) | `_node_content` + плоские метаданные (`file_name`, …) | прод-путь: `/rag/query` и диплом |
| `rag_block_03_bare` | `qdrant-client` напрямую | плоский `{text, source}` | сравнение «руками» |

Обе: dim 1536, distance COSINE. Индексация идемпотентна — при непустой коллекции
переиндексация не запускается (`from_vector_store` / проверка `count() > 0`).

## LlamaIndex vs bare-metal

| Критерий | LlamaIndex (`rag.py`) | Bare-metal (`rag_baremetal.py`) |
|----------|------------------------|----------------------------------|
| Строк кода (ingestion + query, без импортов) | ~8 | ~25 |
| Поддержка форматов из коробки | PDF/DOCX/HTML/MD/… через `SimpleDirectoryReader` + `readers-file` | только то, что прочитаешь сам (здесь — `.md`) |
| Добавить PDF/DOCX | поставить `llama-index-readers-file`, кода не трогать | свой парсер на `pypdf` / `python-docx` + ветвление по расширению |
| Batch-ingestion / async | `IngestionPipeline(num_workers=...)`, `aquery()` из коробки | батчинг и async-обвязка пишутся руками |
| Дебаг top_score / source_nodes | `response.source_nodes` (`.score`, `.metadata`, `.node.get_content()`) | сырые `hits` из `query_points` — видно сразу, но без структуры нод |
| Подмена компонентов (re-ranker, chunker) | `node_postprocessors=[...]`, сменный `node_parser` | каждый шаг переписывается вручную |
| Чанкинг | `SentenceSplitter` (sentence-aware) | наивный: один документ = один чанк |

**Вывод.** В дипломе остаётся LlamaIndex-версия: на том же корпусе она короче,
сразу даёт структурированные `source_nodes` для цитат и мониторинга и позволяет
менять чанкер/реранкер/режим синтеза без переписывания пайплайна. Bare-metal
ценен как способ понять, что фреймворк не магия (тот же `read → chunk → embed →
upsert → search → prompt → LLM`), и как запасной путь, когда нужен полный контроль
над payload. На маленьком корпусе bare-metal давал чуть более высокий top_score
(полный документ в одном чанке), но это артефакт наивного чанкинга, а не
преимущество качества.

## Прогон 5 вопросов

Запуск: `uv run python -m app.services.rag`. Порог fallback — `top_score < 0.3`,
плюс инструкция «отвечай только по контексту» в системном промпте.

| # | Тип | Вопрос | Ответ (кратко) | top-1 source / score | Релевантно | Гипотеза |
|---|-----|--------|----------------|----------------------|------------|----------|
| 1 | хороший | За сколько дней можно вернуть деньги за подписку? | «в течение 14 дней с момента оплаты» | `billing_refunds.md` / 0.566 | да | прямое совпадение по смыслу и словам |
| 2 | хороший | Как включить двухфакторную аутентификацию? | «Профиль → Безопасность → Двухфакторная аутентификация» | `security_2fa.md` / 0.601 | да | термин из вопроса есть в документе дословно |
| 3 | хороший | Какие способы оплаты поддерживает сервис? | «Visa, Mastercard, МИР; Apple Pay / Google Pay; счёт для юрлиц» | `billing_payment_methods.md` / 0.566 | да | один документ закрывает вопрос целиком |
| 4 | средний | Как пригласить коллегу и какую роль назначить? | «Команда → Пригласить (email/ссылка); роль Owner/Admin/Member при приглашении» | `onboarding_roles.md` / 0.434 | да | синтез из двух документов (приглашение + роли); score ниже — вопрос «не теми словами» и размазан по двум файлам |
| 5 | вне базы | Какая завтра погода в Москве? | «В базе знаний нет ответа на этот вопрос» | `offtopic_borscht.md` / 0.171 | нет (и не должно) | fallback сработал: top_score 0.171 < 0.3 |

**Про fallback.** Порог 0.3 — намеренно низкий: у `text-embedding-3-small`
релевантные русские пары вопрос-документ дают cosine ~0.45–0.6, а 0.5 уже
отрезал бы средний вопрос (0.434). Поэтому основной предохранитель — инструкция
в промпте «не нашёл — так и скажи», а порог по score — лишь бэкап для совсем
далёких запросов. На вопросе «как приготовить плов?» (нет в корпусе) top-1 — борщ
со score 0.439 (выше порога), и от выдумки спасает именно промпт, а не порог.

## Настройка качества под большой корпус (SIHIST / «История операций»)

Корпус `data/my-kb` — база `SIHIST/09-Current-State` (страницы текущего
состояния, без списка противоречащих фич) плюс урезанная выгрузка БД.
Параметры ниже управляются через `.env`.

### Что включено

| Параметр | Значение | Зачем |
|----------|----------|-------|
| `RAG_CHUNK_SIZE` / `RAG_CHUNK_OVERLAP` | 1024 / 128 | крупный чанк = раздел фичи целиком, а не пара предложений |
| `RAG_CHUNK_BY_HEADINGS` | true | режем markdown по заголовкам («Назначение», «Текущее поведение», «Контракт»); чанк = раздел страницы |
| `RAG_RETRIEVE_TOP_K` | 25 | достаём широко из большого корпуса |
| `RAG_RERANK_TOP_N` | 10 | в контекст LLM отдаём 10 лучших |
| `RAG_USE_RERANKER` | false | см. «Реранкер» ниже — веса ~2.2 ГБ блокируют старт |
| `RAG_USE_HYBRID` | true | dense + BM25; после смены — full reindex |
| `RAG_SPARSE_TOP_K` | 5 | BM25-кандидатов ≪ dense (`RAG_RETRIEVE_TOP_K`) |
| `RAG_SKIP_DEPRECATED` | true | не индексируем устаревшее (папка «Старая Лента», `superseded_by:`) |

Даже с выключенными reranker и hybrid работает dense-поиск по 1024-токенным
чанкам с header-aware нарезкой + метаданными + фильтром устаревшего — этого
достаточно, чтобы бот отвечал по базе (проверено на старом корпусе: «DCA» →
«Сервисы Депозитария», а не Dollar-Cost Averaging).

### Реранкер (cross-encoder) — как включить надёжно

`RAG_USE_RERANKER=true` даёт заметный прирост качества, но `bge-reranker-v2-m3`
весит ~2.2 ГБ и качается с HuggingFace при первом `RAGService.build()`. Пока идёт
загрузка, `build()` не возвращается и RAG недоступен (503). Кэш HF лежит внутри
контейнера (`/home/appuser/.cache/huggingface`) и теряется при пересборке образа.

Чтобы включить без простоя:

1. Смонтируйте том под кэш HF (переживает пересборку), напр. в `compose.yaml`
   для сервиса `app`:
   ```yaml
   volumes:
     - hf-cache:/home/appuser/.cache/huggingface
   # ... и в общем блоке volumes: hf-cache:
   ```
2. Предзагрузите модель один раз (в том):
   ```bash
   docker compose exec app python -c \
     "from sentence_transformers import CrossEncoder; CrossEncoder('BAAI/bge-reranker-v2-m3')"
   ```
3. Выставьте `RAG_USE_RERANKER=true` и перезапустите `app`.

Альтернатива — более лёгкая модель `BAAI/bge-reranker-base` (~1.1 ГБ).

### Гибрид (dense + BM25)

`RAG_USE_HYBRID=true` — dense (эмбеддинги) + sparse BM25 (`RAG_SPARSE_MODEL`,
по умолчанию `Qdrant/bm25`) через `llama-index-vector-stores-qdrant>=0.10` и
`qdrant-client>=1.16`. Нужен полный reindex: коллекция с named векторами
`text-dense` + `text-sparse-new`. Сервер Qdrant лучше `v1.16+` (клиент ругается
на gap >1 minor к `v1.14`, но hybrid при этом уже работает).

### Метаданные документа

`file_metadata()` проставляет на каждый документ:
`ticket` (SIHIST-XXXX), `layer` (BE/FE/MP/DB), `release_version` (напр. `6.23`),
`deprecated`, `superseded_by`. Технические поля исключены из эмбеддинга
(`EXCLUDED_EMBED_KEYS`), но доступны как фильтры и для отладки источников.

### Что попадает в индекс

- **Текущее состояние.** Индексируется `SIHIST/09-Current-State`. Промпт ответа
  считает эти страницы актуальными и не ищет отдельную версию TO BE.
- **`_actual/` не индексируется.** Сводки писались поверх старого списка фич и
  дублируют те же темы.
- **Выгрузка БД.** Из `БД ИО.md` в индекс идут назначение, сводка, ERD-схема и
  описания таблиц. Построчное заполнение, ERD с данными, SQL/DML и JSON кэша
  отбрасываются при чтении.
- **Устаревшее.** Папка «Фронт Старая Лента» помечается `deprecated=true` по пути
  и при `RAG_SKIP_DEPRECATED=true` не попадает в индекс. Страница legacy-ленты
  внутри `09-Current-State` остаётся: это описание ещё живого пути.
- **Дедупликация.** Строка `superseded_by: SIHIST-1234` в теле документа
  по-прежнему помечает его устаревшим, и такой файл пропускается.

### Зависимости (реранкер + гибрид)

Тяжёлая группа `retrieval` (torch CPU + sentence-transformers + fastembed) ставится
в образ (см. Dockerfile), чтобы reranker/hybrid можно было включить флагом без
пересборки. Локально:

```bash
uv sync --extra retrieval
```

На Linux torch берётся из CPU-индекса PyTorch (без CUDA, см. `[tool.uv.sources]`),
иначе образ раздувается на ~4 ГБ. Веса reranker-модели в образ НЕ пакуются —
качаются в рантайме (см. раздел «Реранкер»).

### Обязательный полный reindex после смены настроек

`_init_rag` индексирует корпус только если коллекция пуста. Смена `chunk_size`,
включение hybrid (нужны sparse-вектора в коллекции) и `skip_deprecated`
**требуют полной переиндексации** уже существующей коллекции:

```bash
# после docker compose up (дождаться healthy):
curl -X POST http://localhost:8000/documents/reindex \
     -H 'content-type: application/json' -d '{"mode":"full"}'
```

`mode=full` удаляет коллекцию и docstore и строит заново; в hybrid-режиме
коллекцию с dense+sparse векторами создаёт сам `QdrantVectorStore` при первом
upsert. Прогресс — в логах `ingestion: ...`, готовность — `rag_ready`.

### Проверка retrieval отдельно от генерации

Чтобы понять, где проблема — в поиске или в ответе LLM — дёргайте `/rag/query`
и смотрите `top_score` / `sources` / `snippet`:

```bash
curl -X POST http://localhost:8000/rag/query \
     -H 'content-type: application/json' \
     -d '{"question":"со сколькими сервисами интегрируется история операций?"}'
```

Если нужный документ есть в `sources` с адекватным `score` — retrieval работает,
и качество ответа тюним промптом; если нет — крутим `top_k` / chunking / hybrid.
